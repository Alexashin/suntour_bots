# Солнечные туры — Telegram + MAX bot

Один backend для двух мессенджеров:

- Telegram: `aiogram 3`, Long Polling.
- MAX:
  - локальная разработка — Long Polling;
  - production — Webhook через HTTPS/443.
- PostgreSQL — общая база пользователей, диалогов, заявок и подписок.
- FastAPI — healthcheck + MAX webhook endpoint.
- Caddy — HTTPS для MAX webhook.
- Docker Compose — запуск всего стека.

## Что уже реализовано

### Клиентский сценарий
1. `/start` / запуск бота.
2. Куда хотите поехать?
3. Какие даты?
4. Сколько человек? Если есть дети — возраст.
5. На сколько ночей?
6. Имя.
7. Как удобнее продолжить общение:
   - в чате;
   - по телефону.
8. Если выбран звонок — бот запрашивает телефон.
9. Формируется заявка, сохраняется в БД и отправляется администраторам.

Для первого MVP поле «куда хотите поехать?» — свободный текст. Ветвление по направлениям можно добавить поверх общей бизнес-логики, не меняя Telegram/MAX адаптеры.

### Данные
Сохраняются:
- платформа;
- ID пользователя;
- username / имя, если платформа их передала;
- телефон, если клиент оставил;
- история заявок;
- текущий шаг диалога;
- подписка на общую рассылку (по умолчанию выключена, только explicit opt-in);
- время подписки и отписки.

### Администраторы
Telegram:
- `/broadcast <текст>` — общая рассылка только подписчикам;
- `/stats` — краткая статистика (можно отключить/не отдавать клиенту как отдельную платную функцию).

MAX:
- заявки можно слать в один или несколько `user_id`/`chat_id`;
- админ-команды можно добавить следующим шагом. В текущем MVP рассылка запускается из Telegram-админки, но база пользователей общая.

## Быстрый запуск локально

1. Скопировать окружение:
   ```bash
   cp .env.example .env
   ```

2. Вставить токены:
   ```env
   TELEGRAM_TOKEN=...
   MAX_TOKEN=...
   ```

3. Для разработки MAX оставить:
   ```env
   MAX_MODE=polling
   ```

4. Указать Telegram ID администратора:
   ```env
   TELEGRAM_ADMIN_IDS=123456789
   ```

5. Запустить:
   ```bash
   docker compose up --build
   ```

6. Проверить:
   ```bash
   curl http://localhost:8000/health
   ```

## Как узнать ID администратора

### Telegram
Написать боту `/whoami`.

### MAX
Добавить нужный аккаунт/чат в `MAX_ADMIN_USER_IDS` или `MAX_ADMIN_CHAT_IDS`.

Чтобы узнать ID в разработке, запустите MAX в режиме polling и отправьте боту сообщение `/whoami`.
Бот ответит своим пониманием `user_id` и `chat_id`, а эти ID также появятся в логах.

## Production для MAX

MAX требует Webhook. Нужны:

- VPS с публичным IP;
- домен, например `bot.example.ru`, с A/AAAA записью на VPS;
- входящий TCP 443;
- доверенный TLS-сертификат;
- `MAX_MODE=webhook`;
- `PUBLIC_DOMAIN=bot.example.ru`;
- `MAX_WEBHOOK_SECRET` — случайная строка 5+ символов.

В проекте есть Caddy. Он автоматически получает сертификат и проксирует:

`https://bot.example.ru/webhooks/max` -> `app:8000/webhooks/max`

После запуска backend автоматически создаёт MAX webhook subscription.

> Для production MAX не используйте Long Polling.

## Рекомендуемый VPS

Для этого проекта без тяжёлой аналитики достаточно:

- 1 vCPU;
- 1 GB RAM — рабочий минимум;
- 2 GB RAM — комфортно для PostgreSQL + backend + Caddy;
- 10–20 GB SSD;
- Linux x86_64/amd64 или arm64;
- статический публичный IP;
- открытые исходящие HTTPS соединения к Telegram и `platform-api2.max.ru`;
- входящий TCP/443 для MAX webhook.

Географически иностранный VPS подходит Telegram. Для MAX важно, чтобы сервер стабильно ходил к API MAX и был доступен MAX по HTTPS. Перед покупкой хостинга желательно проверить связность именно с `platform-api2.max.ru`.

## Важное про токены

Не коммитьте `.env` и не присылайте токены в публичные репозитории. Если токен случайно попал в GitHub/чат с посторонними — перевыпустить.

## Что логично делать следующим этапом

1. Согласовать финальные тексты кнопок/сообщений.
2. Решить, остаётся ли «куда хотите поехать?» свободным текстом или добавляем дерево направлений.
3. Получить реальные Telegram/MAX admin ID.
4. Добавить изображения/логотип.
5. Сделать более удобную админку рассылки: пошагово «создать пост → превью → подтвердить → отправить».
6. Добавить выгрузку CSV/Excel, если клиент подтвердит доп. функцию.


## Подписка и рассылка

По умолчанию новый пользователь **не подписан** на маркетинговую рассылку.

Команды:
- `/subscribe` — явное согласие на рассылку;
- `/unsubscribe` — немедленная отписка.

При подписке бот один раз сообщает, что отписаться можно командой `/unsubscribe`.
В БД фиксируются `subscribed_at` и `unsubscribed_at`.

Для MAX дополнительно используется feature flag:

```env
MAX_MARKETING_BROADCAST_ENABLED=false
```

Если бизнес подтвердит право на маркетинговую рассылку в рамках договора/правил MAX:

```env
MAX_MARKETING_BROADCAST_ENABLED=true
```

Без этого флага Telegram-рассылка работает, а MAX-получатели пропускаются.
